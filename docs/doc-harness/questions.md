## Q1 Standing grant scope

Start with ordinary authorized Doc reads. Require a scoped grant for native file writes, command execution, and actions that send or change data outside DoctorCRE. Enable those actions only where the driver can stop them before dispatch. An alternative is to restrict the first release to Doc tools. Keep the action's target and capability limits in the displayed grant scope. Recommend scoped grants with one decision for repeat use within scope. A live approval can resume only its exact action. Once the claim expires, choose between expiring the approval card immediately or leaving the card available to save a grant until another claim supersedes it. Recommend the second option. A late approval would save the grant once. The next Mac claim would independently check current facts and the grant. Neither a late decision nor a backup takeover would dispatch the original action. A CLI with a native approval interface could supply pre-dispatch requests if it can leave the decision to Doc. Otherwise route the applicable actions through Doc's tools. Prove coverage before enabling an unrestricted driver for actions Doc must control.

## Q3 Business confirmations

Should a standing action grant authorize future DoctorCRE saves or sends by itself? A standing grant authorizes the kind of tool action. The save or send confirmation binds the exact record, text, recipients and version for one transaction.
