# DoctorCRE tools

The engine checks partner identity and a current claim on every model call. The tool names below include the existing MCP tools and two planned knowledge reads. A source is a claim key with an exact record ID, label and app link. The engine supplies labels and links. It validates the input and saves the read count and authorized sources in the claim. The model reads DoctorCRE through Doc's tools. The signed-in app confirms exact changes through the ordinary doors. [Model reads](../new-database.md#model-reads-and-links) · [Shared door rules](../new-database.md#what-every-door-shares)

## Knowledge reads

The [knowledge-store contract](https://github.com/DoctorCRE/doctorcre-engine/pull/1520) supplies these two read-only engine tools. Each call uses one read slot and requires at least one filter. Use the claim partner and current subject access. When `deal_id` is supplied, derive recorded traits and reject conflicting filters. Return current approved revisions with plain-text `notes` and accessible sources. Typed fields carry facts that are naturally data. Both tools return at most ten matches per call, counted by topic for playbooks and by revision for guidance. Keep foreign or inaccessible items and source locators out of the answer. The engine pins revisions supplied as evidence on the answered turn in `doc_knowledge_revision`. Neither read grants permission to save. [Playbook reads](playbooks.md#read-approved-playbooks-and-guidance)

| Tool            | Input                                                                                              | Output and engine checks                                                                                                                                                                                                                                                                                                                                                                           | App confirmation |

If distinct top matches tie, return their titles and IDs. Recheck the selected ID against the accessible top matches for the same filters. A matching deal workflow includes the applicable ordered `playbook_step` to-dos and progress for an exact deal. Check topic, recorded traits, scope and deal access in the engine. | None.            |

The tool receives no app write credentials. For filing or dismissal, only the partner's Home action calls the existing door 21 decision route with the exact filing proposal ID. [F10](flows.md#f10-file-or-dismiss-an-exact-email) If there is no approved engine door, Doc explains the gap and links to the app task where one exists.
